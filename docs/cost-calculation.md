# 原価計算のしくみ（コードの読み方）

原価の計算は、次の2つのファイルに集まっている。画面で掛け算・切り上げは書かず、必ずここを通す（`docs/conventions.md` 2章）。

- `src/lib/cost.ts`：材料1行の原価を出す、いちばん下の部品
- `src/lib/recipe-cost.ts`：メニュー・仕込み品の材料行を集めて、合計と原価率を出す
- テスト：`src/lib/cost.test.ts`・`src/lib/recipe-cost.test.ts`

## 全体の流れ

例：ネギタン塩 ＝ 牛タン 60g ＋ 味ネギ（仕込み品）30g、売価 1,255円（税抜）

```
メニューの材料行
 ├ 牛タン 60g  → 材料1行の原価 lineCost → 0.1円単位で切り上げ → 288.0円
 └ 味ネギ 30g  → 仕込み品を「材料」とみなす → lineCost → 0.1円単位で切り上げ → 27.7円
                   └ 味ネギ1回分の原価 = 材料ごとに切り上げて合計（369円 / 400g）
合計 315.7円（合計では切り上げない） → 原価率 315.7 ÷ 1,255 = 25.2%
```

原価は **0.1円単位**（小数第1位まで）で出す（D-171。それまでは1円単位：D-006）。売価・仕入れ価格は円の整数のまま。

「合計では切り上げない」は、1行ごとにもう0.1円単位になっているので、足しても0.1円単位のまま、という意味。別のやり方として「小数のまま全部足してから、最後に1回だけ切り上げる」もあるが、それはしない（D-006）。足すときも、小数のまま足すと 0.1 + 0.2 = 0.30000000000000004 のような誤差が出るので、0.1円を1とする整数にしてから足す（`addCosts`）。

## 1. 材料1行の原価：`lineCost`（`cost.ts`）

式は **切り上げ（仕入れ価格 × 使用量 ÷ 使える量）**。

```ts
const denominator = toMilli(usableQuantity(source));                       // 使える量（1/1000単位の整数）
const numerator = BigInt(toTenths(source.purchasePrice)) * toMilli(usage); // 仕入れ価格（0.1円単位の整数）× 使用量
return Number((numerator + denominator - 1n) / denominator) / COST_STEP;   // 割って切り上げ、0.1円単位を円に戻す
```

- `toTenths`：円を10倍して整数にする（369円 → 3690、仕込み品の1回分 367.5円 → 3675）。`COST_STEP` は10。

- `toMilli`：量を1000倍して整数にする（2.5g → 2500）。小数のまま掛け算すると誤差が出るため（D-009）。
- `BigInt`：大きな整数でも正確に計算できる型。分数のまま、最後に1回だけ割る。
- `(分子 + 分母 − 1) ÷ 分母`：整数どうしで切り上げる定番の書き方（下で説明）。
- 使用量が0なら0円。仕入れ量が0ならエラー（0で割れないため。保存するときの検証で0は入らないので、画面では起きない）。

### 切り上げの書き方 `(分子 + 分母 − 1) ÷ 分母`

BigInt の割り算は、小数を**捨てる**（7 ÷ 3 = 2）。切り上げの関数はないので、割る前に「分母 − 1」を足して、余りが出るときだけ次の数に届くようにする。

| 計算 | ふつうに割る | 分母−1 を足してから割る | 結果 |
|---|---|---|---|
| 6 ÷ 3（割り切れる） | 2 | (6 + 2) ÷ 3 = 8 ÷ 3 = 2 | 2（上がらない） |
| 7 ÷ 3（余り1） | 2 | (7 + 2) ÷ 3 = 9 ÷ 3 = 3 | 3（上がる） |
| 8 ÷ 3（余り2） | 2 | (8 + 2) ÷ 3 = 10 ÷ 3 = 3 | 3（上がる） |

余りが0なら、足した「分母 − 1」は次の数に届かないので上がらない。余りが1以上なら、必ず次の数に届くので1つ上がる。

実際の例：

- 牛タン 4,800円/kg を 60g：分子 4,800 × 60,000 = 288,000,000、分母 1,000,000（1kg = 1,000g を1000倍）
  → 分子は0.1円単位なので 48,000 × 60,000 = 2,880,000,000、(2,880,000,000 + 999,999) ÷ 1,000,000 = 2880.99… → 小数を捨てて 2880 → **288.0円**（割り切れるので上がらない）
- 味ネギ 369円/400g を 30g：分子 3,690 × 30,000 = 110,700,000、分母 400,000
  → (110,700,000 + 399,999) ÷ 400,000 = 277.74… → 小数を捨てて 277 → **27.7円**（そのまま割ると 276.75 なので、1つ上がっている。27.675円の0.1円単位の切り上げ）

## 2. 使える量：`usableQuantity`（`cost.ts`）

分母の「使える量」は、3つを順にかけて出す。

1. 単位を基本の単位に直す（`toBaseQuantity`、`units.ts`）：kg → g、L → ml。本・袋などの数える単位はそのまま（D-071）。
分母の「使える量」は、2つを順に出す。

1. 単位を基本の単位に直す（`toBaseQuantity`、`units.ts`）：kg → g、L → ml。本・袋などの数える単位はそのまま（D-071）。ml で仕入れたものは ml のまま（比重で g に直すのはやめた：D-163）。
2. 使える割合（D-100）：掃除で減る分を引く。空欄や0のときは100%として扱い、入力の途中でも止まらない（D-128）。

### 使える割合の計算

`使える量 = 基本の単位の量 × 使える割合 ÷ 100`

例：タン 4,800円/kg、掃除で2割減って使えるのは80%、60g 使う

1. 1kg → 1,000g
2. 使える量：1,000g × 80 ÷ 100 = **800g**（4,800円で、使える部分を 800g 買ったのと同じ）
3. 1行の原価：切り上げ（4,800 × 60 ÷ 800）= **360円**（割合を入れないと 288円）

1g あたりで見ると 4.8円 → 6円。使える割合が小さいほど、同じ 60g でも原価が高くなる。

使える割合をかけるところだけは小数で計算し、そのあと 0.001g 単位に丸めている。ずれても 0.001g より小さく、原価が0.1円変わることはまずない。

## 3. メニューの合計：`calcRecipeCost`（`recipe-cost.ts`）

- 材料行ごとに `lineCost` で原価を出し、足すだけ。**合計では切り上げない**（D-006。1行ごとにもう整数なので、足しても整数）。
- 原価率は `costRatio`（`cost.ts`）で、原価 ÷ 売価 × 100。どちらも税抜（D-101）。売価が空欄なら原価率は出さない。
  - 計算した原価率は丸めずに持ち、**画面に出すときだけ**小数第1位に四捨五入する（`format.ts` の `percent`。316 ÷ 1,255 = 25.179…% → 「25.2%」）。
  - 「良好・普通・高い」の判定（`ui.tsx` の `ratioStatus`）は、丸める前の値で比べる。目安の線ちょうどは良いほうに入る（肉なら 28.00% は良好、28.01% は普通）。
  - そのため、28.04% は画面では「28.0%」と出るが、判定は「普通」になる。線のすぐ上のときだけ起きる。
- 材料行の種類ごとの扱い（`calcLines`）：
  - ふつうの材料：`lineCost`
  - 仕込み品：下の 4
  - 仮の材料（創作レシピだけ）：入れた金額をそのまま1行の原価にする（D-096）
  - 鍵がかかった秘密の中身：オーナーが計算して保存した原価（`secret_cost`）をそのまま1行の原価にする（D-148）。社員の画面でも原価と原価率が出るのはこのため

## 4. 仕込み品（`recipe-cost.ts`）

- `prepBatchCost`：1回分の原価。中の材料ごとに `lineCost` で切り上げて合計する（D-019）。
- `prepCostSource`：仕込み品を「1回分の原価で、出来上がり量を仕入れた材料」とみなす。味ネギなら「369円で 400g 仕入れた材料」。
- メニューで 30g 使うと、`lineCost` で 369 × 30 ÷ 400 = 27.675 → 28円。
- 切り上げが2回入るので少し高めに出る。原価は高めに見積もるほうが安全なので、そうしている。
- 仕込み品の中に仕込み品は入れられない（D-020）。

## 5. ほかの丸め

- 売値の目安（創作レシピ）：税抜で1円単位に切り上げ（`price-suggest.ts`、D-143・D-164）。原価369円・肉の目安28%なら 369 ÷ 0.28 = 1,317.8… → 1,318円。原価が0.1円単位でも、整数にしてから割る（D-171）。
- 税込の表示：1円未満を切り捨て。税率を0.1%単位の整数にして整数で計算する（`format.ts` の `withTax`、D-101・D-161）。

## テストで確かめていること（`cost.test.ts`）

- 要件定義書 3.6 の例（合計369円）と一致する
- 割り切れるときは切り上げない
- 小数だと誤差が出る値でも正しく切り上げる
- 合計では切り上げない
- 使える割合・数える単位の計算、ml は ml のまま計算すること
