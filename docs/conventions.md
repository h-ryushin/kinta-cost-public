# 開発規約

このプロジェクトでコードやドキュメントを書くときのルール。迷ったら既存のコードに合わせる。

## 1. 基本方針

- 要件は `要件定義書.md`、決めたことは `docs/decisions.md`、進み具合は `docs/progress.md` を正とする。
- 要件定義書と違うことをするときは、先に `docs/decisions.md` に理由つきで記録する。
- 費用は0円で運用する。有料のサービスやライブラリは使わない。

## 2. お金と計算

- 売価・仕入れ価格は円・税抜の整数で持つ（D-101）。原価だけは0.1円単位（D-171）で、画面では `costYen()`（いつも小数第1位まで）で出す。
- 原価は必ず `src/lib/cost.ts` の関数で計算する。画面で掛け算・切り上げを書かない。
- 編集画面では、原価の金額を1か所にだけ出す（狭い画面は下のバー、広い PC は右のパネル。D-055）。
- 浮動小数点で掛け算してから `Math.ceil` しない（D-009）。
- 切り上げは材料1行ごとに0.1円単位で行い、合計では切り上げない（D-006・D-171）。原価を足すときは `addCosts` を使う（小数のまま足さない）。
- 計算のルールを変えたら、`src/lib/cost.test.ts` にテストを足す。要件定義書 3.6 の例（0.1円単位では合計367.5円。1円単位のころは369円）は必ず通す。

## 3. データ

- 画面からデータを読むときは `useStore()`、書くときは `src/lib/store.ts` の関数を使う。Supabase を画面から直接呼ばない（D-011・D-069）。保存する関数は非同期なので `await` する。
- 入力の検証は `src/lib/types.ts` の Zod スキーマで行う。保存する関数の中でも必ず検証する（画面の検証だけに頼らない）。
- エラーメッセージは利用者が読む日本語で書き、`StoreError` で投げる。画面は `StoreError` だけを表示し、それ以外のエラーは握りつぶさない。
- データの形を変えるときは `STORE_VERSION` を上げ、古いデータの読み込みを考える。データベースも変えるときは `supabase/migrations/` に足し、`docs/database.md` を直す。
- 変更を伴う操作の記録（操作ログ・価格の履歴）は、データベースのトリガーが書く。画面からは送らない（D-033）。

## 4. コード

- TypeScript の `any` は使わない。型は Zod スキーマから `z.infer` で作る。
- ファイル名は `kebab-case.tsx`、コンポーネントは `PascalCase`、関数・変数は `camelCase`。
- 画面（`src/app/**/page.tsx`）は薄く保ち、使い回す部品は `src/components/` に置く。
- 計算・変換などの画面に依存しない処理は `src/lib/` に置く。
- コメントは「なぜそうするか」を日本語で書く。コードを読めば分かることは書かない。
- 決定ログの項目に関わるコードには `D-009` のように番号をコメントで残す。
- ID は `newId()` で作る（D-015）。
- Next.js 16 は以前の版と違う点があるため、新しい API を使う前に `node_modules/next/dist/docs/` を確認する。

## 5. 画面

- 厨房でスマホを使う前提で作る。文字は大きめ、ボタンの高さは 48px（`min-h-12`）以上。
- スマホではナビを画面の下に置き、片手で押せるようにする。
- 色は `src/app/globals.css` で定義した名前（`accent`、`muted` など）だけを使い、色コードを直接書かない。
- 数字の列には `num` クラスをつけて桁をそろえる（大きな1つの数字には付けない）。
- 一覧は `lg`（1024px）以上で表、それより狭い画面はカード。編集画面の2列（右に原価の内訳）は `xl`（1280px）以上だけで、iPad 以下は内訳を下に置き、原価のバーを下に固定する（D-035・D-046）。
- 原価率の状態の色は、必ずアイコンと文字（良好・普通・高い）と一緒に使う。`RatioBadge`・`RatioMeter` を使い、メニューの分類（`category`）を渡す。目安は分類ごとに違う（D-102、`src/lib/ratio-target.ts`）。
- アイコンは `lucide-react` から選び、飾りのアイコンには `aria-hidden` を付ける。
- 画面の見出しは `PageHeader`（タイトル・説明・ボタン・戻り先）を使う。
- 文言は日本語で、です・ます調を基本にする。ボタンは「保存」「やめる」「削除」のように短い動詞にする。
- 削除や上書きなど元に戻せない操作は、自作のダイアログで確認を出す（`useConfirm`）。ブラウザ標準の `confirm`・`alert` は使わない（D-058）。
- 秘密のメニュー・仕込み品は、中身（材料・使用量・メモ）を隠し、金額だけを見せる。印は `SecretBadge`、案内は `SecretLockCard`、オーナーの切り替えは `SecretChoice` を使う（D-060）。
- 価格・量など数字の欄は `NumberInput` を使う。全角は半角に直し、数字以外や上限を超える数字はエラーを出さずに受け付けない。空欄・0 だけ、保存を押したときに欄の下で知らせる（D-036・D-039）。
- ブラウザ標準のプルダウン（`<select>`）は使わない。材料の選択は `ItemPicker`、少ない選択肢は `ChoiceButtons` を使う（D-029）。
- 追加・編集は一覧の中で開かず、専用の画面（`/○○/edit?id=`）で行う（D-030）。
- レスポンシブ：320px（小さいスマホ）で、名前が切れたり、金額が改行されたりしないことを確認する。金額や「○件」には `whitespace-nowrap` を付ける。

## 6. セキュリティ（ログイン機能を作るときから必須）

- APIキーなどの秘密情報は `.env.local` に置き、Git に上げない。`service_role` キーはブラウザに渡さない。
- 権限は画面だけでなく Supabase の RLS で強制する。
- 秘密レシピの鍵と平文は、サーバーに送らない。

## 7. 確認とコミット

- 作業は `develop` ブランチで行い、push も `develop` にする（D-049）。
- `main` は公開中のアプリ（Cloudflare が `main` への push で自動でデプロイする）。`main` への取り込み（merge・push）は、オーナーが「公開して」と承認したときだけ行う。承認なしに `main` を変えない。

- パッケージを追加・削除したら、`rm -rf node_modules package-lock.json && npm install` で入れ直す。npm の不具合（npm/cli#4828）で、`npm install <名前>` だけだと Mac 用のモジュール（`@rolldown/binding-darwin-arm64`）が lockfile から消え、テストが動かなくなるため。
- コミットの前の確認は `&&` でつなぎ、失敗したらコミットしない。
- Dependabot の提案（D-149）は `develop` で取り込む。`main` に来た弱点の提案は `main` で取り込まず、同じ更新を `develop` で行う。取り込むときも上の入れ直しをする。

- コミットする前に `npm run check`（型チェック・lint・テスト）を通す。
- 画面を変えたら `npm run dev` で、スマホ幅（390px）と PC 幅の両方で確認する。
- コミットメッセージは日本語で、1行目に何をしたかを書く（例：「材料の価格履歴を表示する」）。
- 決定をしたら `docs/decisions.md` に、作業が進んだら `docs/progress.md` に追記してから、同じコミットに含める。
